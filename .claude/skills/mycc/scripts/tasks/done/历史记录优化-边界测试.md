## 1. 需求澄清

**背景**：
已实现历史记录优化（只返回最后一个 summary 之后的消息），单元测试已通过（7/7），初步真实数据测试通过（有 summary 的对话）。

**需求**：
用真实的历史对话数据，验证以下边界情况：

1. **无 summary 的短对话**：应返回全部消息
2. **无 summary 的中长对话**：应返回全部消息
3. **大量 summary 的对话**：应只返回最后一个 summary 之后的消息
4. **已测过的有 summary 对话**：确认符合预期

**验证方法**：
- 通过后端 API 请求 `GET /{token}/history/{sessionId}`
- 检查返回的 `messages` 数组长度
- 对比预期值

**预期行为**：
```typescript
如果对话中没有 summary → 返回全部消息
如果对话中有 1 个 summary → 返回 summary 之后的所有消息
如果对话中有多个 summary → 返回最后一个 summary 之后的所有消息
```
